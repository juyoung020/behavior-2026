용어
- **π0.5 (pi0.5)**: Physical Intelligence 의 VLA(Vision-Language-Action, 영상·언어를 받아 로봇 행동을 내는 모델). JAX 구현(openpi).
- **GR00T N1.7**: NVIDIA 의 로봇 기반 모델. 백본 VLM 은 `nvidia/Cosmos-Reason2-2B`(게이트 — HF 에서 동의 필요).
- **fine-tuning(미세조정)**: 사전학습 모델을 대회 데이터로 더 학습.
- **action horizon / chunk**: 한 번 추론에 내는 미래 행동 개수.
- **receding horizon**: 묶음 중 앞 일부만 실행하고 다시 추론하는 방식. **temporal ensembling**: 여러 번 낸 예측을 겹쳐 평균.
- **norm stats(정규화 통계)**: 상태·행동의 평균·표준편차. 학습 전에 계산.

## 1. 베이스라인의 목적

원문: "These baselines are meant to help participants verify the full challenge workflow — loading the demonstration dataset, fine-tuning a policy, running evaluation in OmniGibson, and preparing outputs for submission — and serve as reference implementations for the expected observation and action interfaces of the challenge track."

→ 성능 기준선이라기보다 **전체 파이프라인이 도는지 확인하는 출발점**이다.

## 4. π0.5 (openpi 포크)

### 4.1 설치

```bash
git clone -b behavior https://github.com/wensi-ai/openpi.git $OPENPI_DIR
cd $OPENPI_DIR
git submodule update --init --recursive
GIT_LFS_SKIP_SMUDGE=1 uv sync
source .venv/bin/activate
GIT_LFS_SKIP_SMUDGE=1 uv pip install -e .
```

openpi/JAX 는 Linux 에서 돈다.

### 4.2 학습 설정 `pi05_b1k`

- 원문: "The `pi05_b1k` config fine-tunes the π0.5 base model (`gs://openpi-assets/checkpoints/pi05_base/params`) on the R1Pro robot with a 32-step action horizon."
- docs/b1k.md 의 설정 예: `action_horizon=32`, `num_train_steps=50_000`, `save_interval=10_000`, `robot_config_name="b1k/R1Pro"`, `prompt_from_task=True`.
- 원문(docs/b1k.md): "**`LeRobotB1KDataConfig`** applies B1K-specific repacking, delta-action transforms for joint groups, and prompt loading from LeRobot task metadata." → 몸통·팔 관절은 현재 상태 대비 **델타**로 학습하고 추론 때 되돌린다(로봇 설정의 `needs_delta_comp=True`).
- 입력: 카메라 3대 RGB(설정상 해상도 240×240), proprio 중 base_qvel·trunk_qpos·양팔 qpos·양 그리퍼 qpos 만 사용(`b1k.py` 의 `proprio` 목록).

### 4.3 순서

1. 정규화 통계: `uv run scripts/compute_norm_stats.py pi05_b1k --data.repo_id=$REPO_ID --data.base_config.dataset_root=$DATASET_PATH` → `outputs/assets/pi05_b1k/$REPO_ID/norm_stats.json`
2. 학습(GPU 1장, 원문 명령): `XLA_PYTHON_CLIENT_MEM_FRACTION=0.9 uv run scripts/b1k/train_b1k.py pi05_b1k --exp_name=$EXP_NAME --overwrite --batch_size=64 --data.repo_id=$REPO_ID --data.base_config.dataset_root=$DATASET_PATH`
   - 여러 GPU: `./scripts/b1k/train_b1k.sh pi05_b1k $NUM_GPUS $CUDA_VISIBLE_DEVICES ...`, SLURM: `scripts/b1k/train_b1k.sbatch.sh`
   - 체크포인트: `outputs/checkpoints/pi05_b1k/$EXP_NAME/<step>/`
3. 서빙(원문 명령):

```bash
CUDA_VISIBLE_DEVICES=0 XLA_PYTHON_CLIENT_MEM_FRACTION=0.85 \
uv run scripts/b1k/serve_b1k.py \
    --robot b1k/R1Pro --task b1k/$TASK_NAME --repo-id $REPO_ID \
    --policy.config pi05_b1k --policy.dir $PATH_TO_CKPT \
    --control_mode receding_horizon --action_horizon 16 --port 8000
```

→ 32개를 예측해 앞 16개를 실행하고 다시 추론.

### 4.4 알아 둘 점

- **로봇 이름 불일치**: openpi 의 R1Pro 설정은 관측 키를 `robot::...`(로봇 이름 `robot`)로 찾는데, 평가기 기본 `r1pro.yaml` 은 `robot_r1` → 그대로면 KeyError. 로컬 해결책: `src/sim/configs/r1pro_openpi.yaml`(이름만 `robot`) 을 `--robot-config` 로 넘김. 이 파일이 곧 제출할 로봇 설정이 된다.
- 과제 지시문(prompt)은 `src/openpi/configs/tasks/b1k.py` 에 등록돼 있어야 서빙 때 찾는다(docs/b1k.md Troubleshooting 원문: "Task prompt not found at serve time").
- 메모리: π0.5 는 약 30억 파라미터급이라(π0 논문 기준, 추정) 16GB GPU 한 장으로 전체 미세조정은 어렵다. 공식 레시피 예시도 batch 64(단일 GPU)·8 GPU 기준이다. 2025 상위 팀은 H200 8장을 썼다([2025대회_분석.md](2025대회_분석.md)).

## 5. GR00T N1.7 (Isaac-GR00T 포크)

### 5.1 설치

```bash
git clone https://github.com/wensi-ai/Isaac-GR00T $GROOT_DIR
cd $GROOT_DIR
uv sync --frozen --python 3.10
uv pip install --python .venv/bin/python websockets
source .venv/bin/activate
```

- 원문: "The N1.7 backbone `nvidia/Cosmos-Reason2-2B` is gated. Accept the gate before training." (로컬: juyoung02 계정으로 동의 완료 — [설치기록.md](archive/windows/설치기록.md))

### 5.2 데이터 준비·학습

- `python scripts/b1k/deploy_modality.py $DATA_ROOT` 로 과제 폴더마다 `meta/modality.json` 을 넣는다. 정규화 통계(`meta/stats.json`)는 첫 학습 때 자동 생성.
- LeRobot v3.0 을 그대로 읽는다. 원문: "The GR00T loader reads both the released v3.0 demos and v2.1 natively — no conversion is needed to train."
- 원문: "`scripts/b1k/train_b1k.py` fine-tunes the GR00T N1.7 base model (`nvidia/GR00T-N1.7-3B`) on the R1Pro robot with a 16-step action horizon, tuning the projector and diffusion action head while keeping the vision encoder and LLM frozen."
- 공식 명령은 8 GPU, `--global-batch-size 2048`, `--max-steps 150000`, `--save-steps 1500`, `--decode-only-used-frames`. 체크포인트 `outputs/b1k-$TASK_NAME/checkpoint-<step>/`.

### 5.3 서빙

```bash
CUDA_VISIBLE_DEVICES=0 python scripts/b1k/serve_b1k.py \
    --model-path $PATH_TO_CKPT \
    --modality-config-path examples/b1k/r1pro.py \
    --embodiment-tag NEW_EMBODIMENT \
    --host 127.0.0.1 --port 8000
```

- 원문: "This starts a websocket policy server on port 8000, applying temporal ensembling by default; health-check it with `curl -s http://127.0.0.1:8000/healthz`."
- 서버 코드(`scripts/b1k/serve_b1k.py`)의 `control_mode` 기본값은 `temporal_ensemble`, 다른 선택지는 `receeding_horizon`, `receeding_temporal`(철자 그대로).
- GR00T 설정은 로봇 이름 `robot_r1` 을 쓴다 → 기본 `r1pro.yaml` 로 바로 평가 가능.
- 평가기의 `--replay-action-chunk-size` 는 temporal ensembling 서버에 쓰면 안 된다(평가규칙 원문 경고, [평가기_사용법.md](평가기_사용법.md) 5.3).
- 참고: 2025 2위 팀(Comet) 실험에서는 π0.5 로 turning_on_radio 를 돌렸을 때 Temporal Ensemble 0.00, Receding Horizon 0.25 성공률이었다(보고서 표 3, 설정이 달라 GR00T 에 그대로 적용되지는 않음).

## 6. 평가 (공통)

베이스라인 페이지 원문 명령:

## 7. 성공률 — 공식 수치는 없다

- 2026 베이스라인 페이지·포크 README·문서 어디에도 베이스라인 성공률/q_score 수치가 없다(2026-09-29 확인).
- 기존 [가이드.md](가이드.md) 의 "π0.5 ≈ 10%(radio 과제), GR00T 0%" 는 이번 조사에서 공식 출처를 찾지 못했다.
- 참고가 되는 수치
  - 2026 리더보드 자체점수(검증 전): 방법 이름에 pi05/π0.5 가 들어간 제출 — Autolab "pi05" 100과제 1,000에피소드 Q 0.097(완전성공률 2.0%), ForgeAI "Pi0.5 task embeddings" 20과제 Q 0.024, AIRI "OpenPI Comet dual" 8과제 Q 0.026. (Q 는 100과제로 나눈 값이라 일부 과제만 낸 팀은 낮게 나온다.) → [리더보드.md](리더보드.md)
  - 2025 2위 보고서: 과제마다 그 과제 시연으로만 따로 미세조정(single-task)하면 50과제 중 2과제에서만 성공했고, 7→10→50과제로 함께 학습할수록 성공하는 과제가 늘었다.
  - 로컬 첫 평가(2026-09-29, 제공 π0.5 체크포인트, turning_on_radio 인스턴스 301, `--max-steps 500`): q_score 0.0 — 제한시간을 500 스텝(약 17초)으로 줄인 디버그 실행이라 성능 판단에는 못 쓴다(`outputs/eval_turning_on_radio_20260929_1816/json/`).
