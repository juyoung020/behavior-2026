## 1. 구조 — 프로세스 두 개

1. **정책 서버(policy server)**: 모델을 올려 두고 웹소켓으로 관측을 받아 행동을 돌려준다(기본 포트 8000).
2. **평가기(evaluator)**: OmniGibson(Isaac Sim) 이 장면을 돌리며 매 스텝 관측을 서버에 보내고 받은 행동을 로봇에 적용한다. 끝나면 롤아웃(rollout, 에피소드 1회 실행)마다 JSON 과 MP4 를 쓴다.

원문: "The evaluator connects to the policy server at `--host` and `--port`; the policy server is responsible for receiving observations and returning robot actions."

## 2. 명령과 인자 (eval.py)

```bash
conda activate behavior
cd C:\behavior-2026\BEHAVIOR-1K        # 웹 문서는 저장소 루트에서 실행하라고 한다
python -m omnigibson.eval.eval --task-name turning_on_radio --host 127.0.0.1 --port 8000 \
    --instance-indices 0 --num-rollouts 1 --output-dir outputs/b1k_eval --write-video
```

| 인자 | 기본값 | 설명 |
|---|---|---|
| `--task-name` | (필수) | 과제 id. 목록은 [과제목록.md](과제목록.md) |
| `--host`, `--port` | 127.0.0.1, 8000 | 정책 서버 주소. 평가기는 먼저 `http://host:port/healthz` 를 기다린 뒤 웹소켓을 연다 |
| `--robot-config` | 없음 → `eval/r1pro.yaml` | 로봇 설정 YAML/JSON. `model`·`name` 필수, `type` 키 금지 |
| `--mode` | `public_test` | `train` / `public_test` / `hidden_test`. 웹 문서에는 없고 코드에만 있는 인자 |
| `--instance-indices` | `0` | public_test·hidden_test 에선 0~19 (그 분할 안의 순번). train 에선 인스턴스 id 그대로 |
| `--num-envs` | 1 | 한 번에 같이 돌릴 환경 수. `--instance-indices` 개수와 같아야 함(아니면 오류) |
| `--num-rollouts` | 1 | 인스턴스마다 반복 횟수. 공식 제출은 1 |
| `--replay-action-chunk-size` | 0 | K>1 이면 서버가 준 행동 묶음(chunk)을 K 스텝 동안 요청 없이 실행(아래 5.3) |
| `--max-steps` | 없음 → 사람 평균 × 1.5 | 제한시간(스텝). **공식 결과엔 주지 않는다** |
| `--env-wrapper` | `omnigibson.eval.wrappers.DefaultWrapper` | 관측 프로필. 공식 RGB-D 는 `omnigibson.eval.wrappers.RGBDFullResWrapper` |
| `--policy` | `websocket` | `local` 이면 서버 없이 0 행동만 냄 — 평가기 동작 점검용 |
| `--output-dir` | `/tmp/b1k_eval` | 결과 폴더. `json/`, `videos/` 아래에 저장 |
| `--write-video` / `--no-write-video` | 끔 | MP4 저장. **제출에 필수** |
| `--video-fps` | 30 | 영상 fps |
| `--headless` / `--no-headless` | 켬(headless) | 창 없이 실행 |

그 밖에 코드에 고정된 것
- 시드 0 고정(`DEFAULT_EVAL_SEED`), `partial_scene_load=True`(과제에 필요한 방만 불러옴 — 방 목록은 `B100_task_misc.csv`).
- 제어 30Hz, 물리 120Hz, 렌더 30Hz(`generate_basic_environment_config`).
- 환경변수 `OMNIGIBSON_KEEP_VIEWER_CAMERA=1` 이 아니면 headless 때 디버그 뷰어 카메라를 만들지 않는다(속도용).

## 3. 인스턴스 번호와 제한시간

- 평가 인스턴스 id 는 301~340 (`TEST_INSTANCE_IDS = list(range(301, 341))`). 앞 20개(301~320)가 public, 뒤 20개(321~340)가 hidden.
- `--mode public_test --instance-indices 0..9` → id 301~310 = **점수 보고용**. 인덱스 10~19(id 311~320)는 연습용.
- hidden 인스턴스 파일은 배포되지 않는다(로컬 `datasets\2026-challenge-task-instances\scene_test\` 에 `public` 만 있음).
- 제한시간 = `int(사람 평균 스텝 × 1.5)`. 사람 평균은 `datasets\2026-challenge-task-instances\metadata\task.jsonl` 의 `length`. 예: turning_on_radio 2149.64 스텝 → 3224 스텝(약 107초).
- 인스턴스마다 로봇은 먼저 기본 자세로 리셋되고, 인스턴스 파일의 시작 위치로 옮겨진 뒤 물리를 25 스텝 안정화하고 시작한다.

## 4. 관측 — 래퍼(wrapper)와 로봇 설정

### 4.1 제공 래퍼

| 래퍼 | 모달리티 | 해상도 (헤드 / 손목) | 원문 |
|---|---|---|---|
| `DefaultWrapper` | rgb | 224×224 / 224×224 | "Low-resolution RGB observations at `224 x 224`, plus proprioception. This is useful for faster debugging but does not include depth." |
| `RGBDFullResWrapper` | rgb + depth_linear | 720×720 / 480×480 | "Official RGB + depth challenge observations, with a `720 x 720` head camera and `480 x 480` wrist cameras." |

- 래퍼의 `camera_spec()` 이 정한 모달리티·해상도는 **환경을 만들 때** 로봇 설정에 박힌다(여러 환경을 묶으면 해상도를 나중에 못 바꾸기 때문). 그래서 `r1pro.yaml` 의 `obs_modalities`·카메라 해상도(1080)는 실제로는 래퍼 값으로 덮인다.
- 직접 래퍼를 만들 수 있다. 조건은 RGB·depth·proprio 만 넘길 것([평가규칙_원문.md](평가규칙_원문.md) 4절).

### 4.2 정책이 받는 관측 딕셔너리 (flatten 된 키)

평가기는 OmniGibson 관측을 `상위::하위` 로 펼친 뒤(`flatten_obs_dict`) 몇 가지를 더한다. 로봇 이름이 `robot_r1`(기본)일 때:

| 키 | 내용 |
|---|---|
| `robot_r1::proprio` | proprio 61차원 (아래 표) |
| `robot_r1::robot_r1:zed_link:Camera:0::rgb` | 헤드 RGB. 4채널(RGBA) — openpi 래퍼는 `[..., :3]` 로 자름 |
| `robot_r1::robot_r1:left_realsense_link:Camera:0::rgb`, `...right_realsense_link...::rgb` | 손목 RGB |
| `...::depth_linear` | 깊이(미터). RGBDFullResWrapper 일 때만 |
| `robot_r1::cam_rel_poses` | 로봇 베이스 기준 카메라 상대 pose(위치3+쿼터니언4) × 카메라 수 |
| `task_id` | 과제 번호(0~99) |

- 모든 값에 **맨 앞 배치 차원(num_envs)** 이 붙어 온다(`_batch_obs` 가 `th.stack`). num_envs=1 이어도 `(1, ...)`.
- 로봇 이름이 바뀌면 키가 바뀐다. **openpi 베이스라인 설정은 로봇 이름을 `robot` 으로 가정**(`robot::robot:zed_link:Camera:0::rgb`, `robot::proprio`) → 기본 `r1pro.yaml`(`robot_r1`)로 돌리면 KeyError. 로컬에선 이름만 바꾼 `C:\behavior-2026\src\configs\r1pro_openpi.yaml` 로 해결해 두었다. GR00T 베이스라인 설정은 `robot_r1` 을 쓴다.

## 5. 행동과 통신 프로토콜

### 5.1 행동 23차원 (기본 r1pro.yaml, `ACTION_QPOS_INDICES["R1Pro"]`)

| 구간 | 부위 | 컨트롤러 (기본) |
|---|---|---|
| 0:3 | base | HolonomicBaseJointController, 속도 명령. 입력 [-1,1] → 출력 x·y ±0.75 m/s, 회전 ±1 rad/s |
| 3:7 | torso(trunk) 4관절 | JointController, 절대 위치 |
| 7:14 | 왼팔 7관절 | JointController, 절대 위치 |
| 14 | 왼쪽 그리퍼 | MultiFingerGripperController, smooth |
| 15:22 | 오른팔 7관절 | JointController, 절대 위치 |
| 22 | 오른쪽 그리퍼 | MultiFingerGripperController, smooth |

- 기본 설정: `action_normalize: false`, `grasping_mode: assisted`, 카메라 관절은 NullJointController.
- 컨트롤러를 바꾸면(예: IK) 행동 차원이 달라진다. 서버가 돌려주는 배열 길이 = `robot.action_dim`.
- 2025 평가 문서에 컨트롤러 변경 예시(델타 관절, IK 절대/델타 pose, 그리퍼 관절 제어)가 있다 → [raw/site_challenge_archive_2025_evaluation.md](../../raw/site_challenge_archive_2025_evaluation.md) "Configure Robot Action Space".

### 5.2 웹소켓 프로토콜 (network_utils.py)

- 연결 전 `GET /healthz` 가 응답할 때까지 기다린다.
- 메시지는 msgpack(넘파이 배열 확장). 평가기 → 서버: 관측 딕셔너리. 서버 → 평가기: `{"action": 배열}`.
- 에피소드 시작 때 평가기가 `{"reset": True}` 를 보낸다 → 서버는 정책 상태(행동 버퍼 등)를 비워야 한다.
- 웹소켓 설정: `max_size=None`(큰 이미지 허용), `ping_interval=60`, `ping_timeout=300`.
- 서버를 직접 짤 때 도우미: `omnigibson.eval.utils.network_utils.WebsocketPolicyServer` (정책 객체에 `act(obs)`·`reset()` 이 있으면 됨). 원문: "The helper server implementation is `WebsocketPolicyServer` in `OmniGibson/omnigibson/eval/utils/network_utils.py`, and the evaluator-side client is `omnigibson.eval.policies.WebsocketPolicy`."

### 5.3 행동 묶음 재생 (선택)

- `--replay-action-chunk-size K` (K>1): 평가기가 요청에 예약 필드를 넣어 K 개 행동을 달라고 하고, 서버는 `action`(첫 행동)과 `action_chunk`(K 개)를 함께 돌려준다. 첫 행동을 바로 쓰고 나머지 K−1 개는 서버에 묻지 않고 실행 → 통신 횟수가 줄어 빨라진다.
- **예약 필드 이름은 코드상 `__action_chunk_size__`** 다(`ACTION_CHUNK_REQUEST_KEY`, 로컬 `docs\challenge\evaluation.md` 도 같음). 웹페이지에는 마크다운 렌더링 때문에 밑줄이 굵은 글씨로 바뀌어 `action_chunk_size` 로 보인다 — 서버 구현 때 주의.
- 원문 주의: "Only enable replay when the server returns an action sequence intended to be executed open-loop from the current observation, such as one receding-horizon policy chunk, and choose `K` so replay never crosses the policy's replanning boundary."
- 원문 주의: "Do not enable it for temporal ensembling or for a server that repeatedly re-runs or blends the policy on the same stale observation; those actions are not equivalent to normal closed-loop evaluation."
- 서버가 `action_chunk` 를 안 주면 경고를 남기고 매 스텝 요청으로 돌아간다.

## 6. 결과물

형식 전체(필드 뜻·단위·계산식·점수 집계)는 [벤치마크_출력형식.md](벤치마크_출력형식.md).

- `<output-dir>/json/<task>_<instance_id>_<rollout_id>.json` (예: `turning_on_radio_301_0.json`)
- `<output-dir>/videos/<task>_<instance_id>_<rollout_id>.mp4` — 672×448 합성(왼쪽 손목 2개 224×224 세로, 오른쪽 헤드 448×448). `--write-video` 는 로봇 설정에 `eval.camera_sensor_names` 의 `head`·`left_wrist`·`right_wrist` 세 역할이 모두 있어야 한다.
- JSON 필드: `task`, `instance_id`, `rollout_id`, `steps`, `success`, `agent_distance{base,left,right}`, `normalized_agent_distance{...}`, `q_score{final}`, `time{simulator_steps, simulator_time, normalized_time}`.
- 끝나면 로그에 `Eval summary: 성공수/전체 | mean q_score=...` 가 찍힌다.

## 7. 점수 직접 계산하기

- 에피소드 점수: `q_score.final` (계산 방식은 [평가규칙_원문.md](평가규칙_원문.md) 6.2).
- 공식 방식에 맞는 자체 계산: 과제별로 인스턴스 0~9 의 q_score 평균(없는 인스턴스는 0) → 100개 과제 평균.

```python
import json, glob, collections
per_task = collections.defaultdict(list)
for f in glob.glob(r"<출력폴더들>\**\json\*.json", recursive=True):
    d = json.load(open(f))
    per_task[d["task"]].append(d["q_score"]["final"])
score = sum(sum(v) / 10 for v in per_task.values()) / 100   # 인스턴스 10개, 과제 100개 기준
```

- 주의: 공식 도구 `python -m omnigibson.eval.utils.score_utils -i <폴더> -o <폴더>` 는 2025 형식을 그대로 요구한다 — 입력 폴더 이름 `<track>.<testset>.<team>.<affiliation>.<date>`(track 은 `standard`/`privileged`), 그 안에 `json/`. 그리고 `public` 이면 과제당 **20개**로 나눈다(`NUM_PUBLIC_TEST_INSTANCES = 20`) → 0~9 만 넣으면 점수가 절반으로 나온다. 참고용으로만.
- 같은 모듈의 `--generate_task_jsonl` 은 데모에서 사람 통계(`task.jsonl`)를 다시 만드는 기능이다.

## 8. 속도·자원

- 기준 장비(RTX 4090)에서 무작위 행동 FPS: RGB 224 → 24.55, RGB 720/480 → 20.62, RGB-D 224 → 16.55, RGB-D 720/480 → 13.52. 장면 로딩 150~300초(웹 원문 표).
- 정책 추론 시간이 더해지므로 실제로는 더 느리다. 2025 1위 팀 보고서 요약: 500 에피소드(50과제×10)를 머신 한 대로 돌리면 약 10일이라 RTX 4090 20대로 병렬화해 2일 안에 끝냈다 → [raw/arxiv_2512.06951_fulltext.md](../../raw/arxiv_2512.06951_fulltext.md) 8.3절. 2026 은 1,000 에피소드다.
- `--num-envs` 로 한 프로세스에서 여러 인스턴스를 같이 돌릴 수 있게 됐다(v3.9.3-post1 릴리스 노트의 "Merge vector into main"). GPU 메모리가 허락하는 만큼만.
- 이 PC(RTX 5070 Ti 16GB)는 기준 장비보다 VRAM 이 작다. 시뮬레이터와 정책 서버를 한 GPU 에 같이 올리면 빠듯하다 → [가이드.md](가이드.md).
