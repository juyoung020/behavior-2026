## 막힌 점

1. **`setup.ps1` 이 Isaac Sim 확인에서 멈춤.** 휠을 임시 폴더에 받아 pip 설치 → `import isaacsim` 실패 →
   임시 폴더 삭제. PowerShell 5.1 기록(Start-Transcript)에는 pip 출력이 남지 않아 원인을 알 수 없었다.
   → `install_isaacsim.py` 로 휠을 캐시에 받아 두고 pip 출력을 그대로 보며 설치,
   setup.ps1 의 후처리(websockets 프리번들 제거, cffi 1.17.1)와 JoyLo · 평가 의존성까지 이어서 한다.
2. **디스크.** 공식 에셋 함수는 zip 전체(31.5 GB)를 받은 뒤 풀어서, 푸는 동안 약 66 GB 가 동시에 필요하다.
   → `stream_assets.py` 가 HTTP 범위 요청으로 zip 안 파일을 하나씩 바로 풀어 최대 34.7 GB 로 줄였다.
   `.partial` 에 풀고 끝나면 이름을 바꾼다(공식 함수는 폴더가 있으면 '설치됨' 으로 넘어가서).
3. **`-Eval` 은 `-JoyLo` 를 요구한다.** 가이드 초안의 명령에 빠져 있었다.
4. **한글 깨짐.** Windows PowerShell 5.1 창은 CP949 로 읽는다 → 실행 스크립트에서
   `[Console]::OutputEncoding = UTF8`, `.ps1` 은 BOM 있는 UTF-8 로 저장.
5. **Git Bash 에서 `wsl.exe ... /mnt/c/...` 경로가 바뀜** (exit 127) → `MSYS_NO_PATHCONV=1`.
   WSL 로 넘길 명령은 따옴표 안 변수가 풀려 버리므로 스크립트 파일로 만들어 실행한다.
6. **setup.ps1 의 앞 단계도 조용히 실패했다.** Isaac Sim 을 따로 설치한 뒤 보니 torch 가 **CPU 판(2.7.0+cpu)** 이었고
   `bddl3` · `OmniGibson` 이 아예 설치돼 있지 않았다(pip 출력이 기록에 안 남아 몰랐다).
   → `fix_behavior_env.sh`: torch 2.7.0 cu128 · torch-cluster(cu128) 재설치, bddl3 · OmniGibson[eval] 설치,
   마지막에 torch 가 다시 CPU 판으로 바뀌지 않았는지 확인. 로그 `logs\fix_behavior_env.log`.
   pip 에 넘기는 editable 경로는 `/c/...` 가 아니라 `C:/...` 형식이어야 한다.
   `import omnigibson` 이 `warp` 를 요구해 `warp-lang==1.12.0`(OmniGibson `primitives` 옵션과 같은 버전)을 추가했다.
   OmniGibson 을 Isaac Sim 뒤에 깔아 Isaac Sim 이 고정한 버전 일부(websockets, click, Pillow, psutil 등)가
   바뀌었다 — 시뮬레이터를 띄워 문제가 없는지 확인한다.
7. **로그 감시가 기록을 막았다.** 설치 창들은 PowerShell `Add-Content` 로 로그를 쓰는데, Git Bash 의 `tail -F` 로
   같은 파일을 감시하자 그 뒤로 기록이 실패했다(작업 자체는 계속됨). 로그를 볼 때는 `tail -F` 대신 한 번씩 읽는다.
8. **HuggingFace 요청 한도(429).** 데모를 `annotations/*.*` 로 받으려다 `*` 가 폴더 경계를 넘어 전체 과제의
   작은 파일 2만여 개를 요청했고, 같은 계정의 에셋 다운로드까지 대기에 걸렸다. → 데모는 에셋이 끝난 뒤
   정확한 경로(`annotations/task-0000/*` 등)로 다시 받는다.

9. **동작 확인은 공식 방법으로.** 따로 만든 시험 스크립트를 conda 활성화 없이, 창 없이 돌렸을 때 Isaac Sim 이
   numpy 행렬 계산(MKL)에서 죽었지만, 사용자가 공식 절차대로(conda activate behavior 후 공식 예제) 돌리면 오류가 없었다.
   → 시험 스크립트와 그에 맞춘 설정 변경(BLAS 를 OpenBLAS 로)은 되돌렸다. 확인은 가이드 3단계 명령을 기준으로 한다.
   (pymeshlab 이 끌어온 pip msvc-runtime 14.44 가 conda 런타임 14.51 을 덮어쓴 것은 공식 설치 순서의 결과와 같게
   conda vc14_runtime 재설치로 되돌려 두었다.)
10. **WSL 기본 CUDA 링크가 12.9 로 넘어갔다(09-29 20:10).** TensorRT 설치(`libnvinfer-dev 10.13.3.9+cuda13.0`)가 `cuda-cudart-dev-12-9` 를 끌어오면서
    update-alternatives 자동 모드가 `/usr/local/cuda` 를 bin/ 이 없는 12.9 로 바꿨다(`/var/log/apt/history.log`).
    → `sudo update-alternatives --set cuda /usr/local/cuda-12.8` (cuda-12 도 같이). 수동 모드라 다음 설치 때 다시 안 바뀐다. 빌드는 12.8 경로를 직접 지정.
11. **PhysX 빌드 (엔진 자체 구현 층 0).** 공식 omni.physx 가 링크한 PhysX 는 **checked** 빌드다(DLL 안에 PX_CHECK 오류 문자열이 있음) →
    재생 도구는 checked 에 링크한다(OmniPVD 지원도 checked·profile 에만 있음, release 는 `PX_SUPPORT_OMNI_PVD=0`).
    GPU 커널은 공식 cmake 가 SASS 70~120 을 다 만들어 오래 걸리므로 로컬 사본의 `source/compiler/cmakegpu/CMakeLists.txt` 한 줄을
    `SASS "120" PTX "120"` 으로 바꿨다(원본 `.orig` 로 보관, 결과 코드는 같음). CUDA 는 `CUDACXX=/usr/local/cuda-12.8/bin/nvcc`.
    링크 때 PhysXPvdSDK 가 GPU 모듈 함수 `PxSetPhysXGpuProfilerCallback` 을 찾아서, CPU 재생기에는 빈 함수(`replay/px_gpu_stub.cpp`)를 넣었다.
