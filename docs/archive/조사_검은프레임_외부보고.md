# 조사: 검은 프레임 — 외부 보고·답변 (2026-09-30)

읽기만 했다(글·댓글·메시지 작성 없음). 대상: BEHAVIOR-1K GitHub 이슈·PR·Discussions·릴리스 노트, isaac-sim/IsaacSim·IsaacLab 이슈, NVIDIA 문서·포럼, BEHAVIOR-1K Discord(사용자 브라우저에 이미 로그인된 세션으로 검색만).
우리 증상 정의는 [평가기_가속설계.md](../평가기_가속설계.md) 5.2 참고: (A) 다른 프로세스 VRAM 5 GiB 넘으면 RGB 전부 검정, (B) 큰 장면에서 일부 카메라 RGB 가 3 스텝 주기로 검정(판마다 운), (스텝0) 첫 관측 한 장만 검정.

## 1. 결론 한 줄

**우리 (B) 와 같은 증상(3 스텝 주기, depth 정상, 단일 GPU)을 보고한 곳은 BEHAVIOR 쪽(GitHub·Discord)에도 Isaac Sim 쪽에도 없다.** 가장 가까운 단서는 Discord 의 "평가 이미지가 proprio 보다 2 스텝 늦다" 보고(렌더 결과가 3 칸 고리로 돌아간다는 우리 해석과 맞음)와, Windows 11 + AMD 내장 GPU PC 에서 내장 GPU 를 끄자 RTX 실시간 깜빡임이 사라졌다는 Isaac Sim 이슈다.

## 3. 대회 규칙·Discord 운영진 답 (4번 항목)

- 재실행: 규칙은 "cherry-pick 금지, 인스턴스마다 정해진 1 회 롤아웃"([평가규칙_원문.md](../평가규칙_원문.md) 6.4). Discord 2026-09-29 vikb193 "크래시로 metrics JSON 이 없으면 그 인스턴스만 다시 돌려도 되나" → 운영진 stef: 원인을 물으며 "If it is something like resources issue then it could be ok." **검은 프레임 판 재실행에 대한 명시 답은 없다.** 우리 경우는 크래시가 아니라 결과가 나온 판이므로, 재실행하려면 먼저 물어보는 게 안전하다.
- 평가기 렌더 변경: Discord 2026-09-12 운영진 Wensi(Vince) Ai "After discussion, it's ok to do the sparse rendering for self evaluation…" + 변경 내용을 첨부하라는 취지(원문 뒷부분 잘림). 09-29 에도 "disclosed like the sparse-rendering changes" 방식으로 PR #2357 패치 허용(stef "Yes"). → **렌더 방식 변경은 공개·첨부 조건으로 허용된 선례가 있다.** 렌더 설정(Kit 인자) 변경 자체를 다룬 답은 없다.

- 공식 FAQ(behavior.stanford.edu/other/faq.html)·known issues 페이지에 검은 프레임 언급 없음.

## 4. 시도해 볼 만한 것 (우선순위)

1. **렌더 완료까지 기다렸다 읽기** (Discord #1 근거): 스텝마다 `PostProcessDispatcher.referenceTime` 이 앞으로 갈 때까지 렌더·읽기(= `rep.orchestrator.step(wait_for_render=True)` 와 같은 방식). 2 스텝 지연과 3 스텝 주기 검정이 같은 3 칸 고리에서 나온다면 둘 다 없어질 수 있다. 평가기 코드 변경이므로 공개 필요(sparse rendering 선례).
2. **AMD 내장 GPU 배제** (#509·#507 근거): ① Kit 인자 `--/rtx/realtime/mgpu/enabled=false`, `--/renderer/multiGpu/autoEnable=false` ② Windows 설정 > 그래픽에서 python.exe 를 고성능(NVIDIA) 지정 ③ 효과 없으면 장치 관리자에서 AMD Radeon 내장 그래픽 "사용 안 함"(되돌릴 수 있음, 화면 출력이 NVIDIA 에 연결돼 있는지 먼저 확인). 3 스텝 주기라 5 판 연속 0 기준으로 판정.
3. 드라이버: 현재 591.86 은 알려진 595.xx 문제 대상 아님. NVIDIA 검증판 580.88 로 내리는 것은 마지막 수단(사용자 결정 사항).
4. `/exts/isaacsim.core.throttling/enable_async` — 이미 false, 시험 불필요.
5. 그래도 안 되면 지금 방침 유지: `--black-guard=abort` 로 무효 처리, 제출은 Linux GPU 장비. 재실행 허용은 Discord #support 에 물어 확인(지금은 답 없음).
