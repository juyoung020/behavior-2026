용어
- **Q / q_score**: 부분 점수 평균. **SR(success rate)**: 완전 성공 비율.
- **flow matching**: π0.5 행동 전문가(action expert)가 잡음에서 행동 묶음을 만들어 내는 생성 방식.
- **RFT(rejection sampling fine-tuning)**: 정책을 여러 번 돌려 성공한 것만 모아 다시 학습.
- **inpainting(행동 이어붙이기)**: 이전 묶음의 남은 행동을 새 예측의 앞부분으로 고정해 이음새를 부드럽게.

## 1. 2025 대회 개요와 올해와의 차이

- NeurIPS 2025 행사. 50과제, 시연 10,000개(1,200시간 이상). 2025-09-02 시작, 마감 2025-11-16 AoE(하루 연장), 발표 2025-12-06~07.
- 트랙 두 개: Standard(원문 "RGB + depth + instance segmentation + proprioception") / Privileged(시뮬레이터 정답 조회 가능). 트랙별 상금 1등 $1,000 + GeForce 5080 등.
- 18팀 참가(원문 "we have received submissions from 18 teams across academia, industry, and individuals; participating from 4 countries (US, China, Canada, South Korea)").
- 2026 과의 규칙 차이는 [평가규칙_원문.md](평가규칙_원문.md) 9절. 핵심: 분할 금지, 트랙 1개, 과제 100개, 제한시간 2배→1.5배, 로봇 자유.

## 3. 1위 — Robot Learning Collective (π0.5 개조)

README 원문 첫 줄: "**1st Place | Public Leaderboard: 26% | Private Leaderboard: 26%**" (여기서 26% 는 Q 0.26 을 뜻한다)

### 3.1 모델 (README "Solution Summary" 요약)

- π0.5 + openpi 기반. 원문: "Replaced language model with 50 trainable task embeddings (no text processing)" — 언어 지시문 대신 과제별 학습 임베딩.
- 상관 잡음: 원문 "Correlated noise for Flow Matching: noise is sampled from N(0, 0.5*I + 0.5*Σ) instead of independent noise, where Σ is the action correlation matrix"
- 행동 전문가의 각 층이 VLM 여러 층의 KV 를 학습 가중치로 섞어 참조.
- "System 2": 과제 진행 단계(과제당 5~15단계, 시간 위치로만 나눔)를 VLM 이 예측하고, 투표로 부드럽게 넘겨 다시 입력으로 넣는다(비마르코프 문제 완화).

### 3.2 학습

- 원문: "Multi-step Flow Matching: 15 action expert predictions (with different time and noise sampled) per each VLM step to reduce training variance"
- 원문: "Delta action space with per-timestamp normalization"
- FAST 보조 손실 0.05, 단계 예측 손실 0.1.
- 원문: "Trained on 224x224 RGB images + proprioception states only" — **깊이·분할을 안 썼다 → 2026 관측 규칙에도 맞는 입력**.
- 50과제 동시 학습 → 성적에 따라 과제 묶음을 나눠 추가 학습 → 최종 체크포인트 4개를 과제 ID 로 전환.
- 비용: 보고서 원문 "Our total competition budget was" 약 $13k (개인 $3k + Nebius 후원 $10k), H200 8장으로 50과제 학습에 15일, 묶음별 추가 학습 약 1주씩. 원문 결론: "None of our models fully converged—despite training nearly continuously for a month, only ∼" 약 2 에폭(수식 기호 때문에 문장 일부만 인용).

### 3.3 추론 요령

- 30개 예측 → 26개 실행, 4개는 다음 예측의 앞부분으로 고정(soft inpainting, 잡음 제거 단계의 앞 70% 에만 적용).
- 3차 스플라인으로 26개를 20스텝에 실행(1.3배 가속). 그리퍼 상태가 바뀔 때는 가속 끔.
- **그리퍼 복구 규칙**: 원문 "if the gripper is closed and it was never closed in training data for this particular task at the same stage, we treat it as a failed grasp and completely open the gripper." 효과 원문: "This correction rule alone approximately doubled our success rate in selected tasks where grabbing objects was a common failure mode."
- turning_on_radio 전용 규칙 하나(마지막 단계에서 실패하면 2단계 되돌림).

### 3.4 평가 인프라

- 요약: 머신 한 대로 500 에피소드 약 10일 → RunPod RTX 4090 20대로 병렬화, 2일 안에 완료. 결과는 Cloudflare R2 에 자동 동기화, 크래시 난 에피소드는 다시 돌리는 간단한 분배기.
- 공식 평가 스크립트는 바꾸지 않았다(원문 "avoided to keep the official eval script unchanged").

### 3.5 실패 원인 분석 (15개 과제 표본)

원문 목록에서: "Dexterity: Clumsiness—the robot cannot reliably pick up or release items. This is the dominant problem, accounting for around one-third of failures" / "Order: Progress errors—wrong action sequence." / "Robot fell: While attempting to squat to pick an item from the floor, the robot sometimes starts to fall backward" / "Head camera visibility: The head camera does not cover the floor in front of the robot or shelves above the head"

### 3.6 결론·제안 (원문)

- "Pretrained VLA models are essential. Our attempts to train a smaller model (same architecture but smaller transformers) from scratch didn’t show promising results."
- "Collecting corrective actions: We believe that even a comparatively small number of hours of demonstrations collected from states where the model fails can significantly improve its robustness"
- "VLM as System 2: Modern VLMs exhibit good video understanding. With no strict budget on using cloud APIs, powerful VLMs prompted with task-specific “checklists” may offer a strong effort/results trade-off"

### 3.7 공개 체크포인트

- `IliaLarchenko/behavior_submission` — 대회 제출에 쓴 4개 체크포인트(Apache-2.0, 약 50 GB). README 에 과제 ID ↔ 체크포인트 표.
- `IliaLarchenko/behavior_50t_checkpoint` — 50과제 동시 학습 1단계 체크포인트(약 12.6 GB). 원문: "our guess is that it can achieve around 15-20% q-score."
- 서버 스크립트는 평가기가 주는 task_id 로 체크포인트를 고른다(`--task-checkpoint-mapping`).

## 4. 2위 — Comet (NVIDIA Research, π0.5 + RFT)

- 초록 원문: "Through careful ablation studies, we reveal the scaling benefits in both the pre-training and post-training phases, leading to a validation Q-score of 0.345, significantly surpassing previous state-of-the-art performance." (0.345 는 대회 뒤 공개 인스턴스 기준)
- 대회 중 결과: 원문 "our solution completes 22 tasks out of the 50 household tasks, achieving a Q-score of 0.2514"

### 4.1 데이터

- 공식 시연 외에 약 3.6K 궤적 추가(모션 플래너 + 오프라인 RL 롤아웃). 원문: "Beyond the official teleoperated dataset, we further incorporate ∼" 로 시작하는 문장(기호 때문에 전체 인용 생략).
- 데이터 공개: https://huggingface.co/datasets/delinqu/comet-1.5k (README 링크)

### 4.2 학습

- 사전학습: 1·7·10·50과제로 비교 → 과제를 많이 섞을수록 성공 과제 수가 늘었다. 과제 하나만 따로 학습하면 성공 과제 2개뿐.
- 후학습 RFT: 로봇 초기 자세를 흔들어 롤아웃 → 성공한 것만 모아 재학습, 3회 반복(회당 평균 8,500 궤적 → 최종 1,469개 선별).
- H200, 장치당 배치 64, 50과제 사전학습 50k 스텝, 학습률 2.5e-5(RFT 때 2.5e-6).
- 검증 Q 변화(표 2): 사전학습 0.192 → 후학습 0.345, 체크포인트들의 최선만 모으면 이론상 0.611.

### 4.3 소거 실험 (turning_on_radio, 표 3·4 — 원문 표 수치)

| 설정 | 결과(성공률) |
|---|---|
| 실행 방식: Temporal Ensemble / Receding Temporal / Receding Horizon | 0.00 / 0.00 / 0.25 |
| action horizon 8 / 16 / 50 / 32 | 0.00 / 0.10 / 0.25 / 0.30 |
| 입력: RGB+Depth / RGB+Point Cloud / RGB | 0.20 / 0.30 / 0.30 |
| 해상도: 224·224 / 헤드 720·손목 480 | 0.30 / 0.60 |
| 행동: 델타 관절 / 절대 관절 | 0.00 / 0.30 |
| 샘플링: 15Hz / 30Hz | 0.00 / 0.30 |
| proprio 입력 없음 / 있음 | 0.00 / 0.30 |
| 스킬 가중(조작:이동=2:1) / 없음 | 0.30 / 0.30 |

원문 해석 문장: "Results shows that relative-action parameterization and the removal of state both lead to worse results, suggesting that absolute action anchoring and explicit system observability are essential for stable closed-loop optimization."

주의: 한 과제·표본 적은 실험이다. 1위는 델타 행동(시점별 정규화)을 썼다 — 두 팀 결론이 다르므로 그대로 믿지 말고 직접 확인.

## 5. 그 밖의 팀

## 6. 2026 에 쓸 교훈 (이 조사의 해석)

1. **부분 점수를 넓게**: 1위 점수의 약 절반이 부분 점수. 100과제 모두 제출하고, 과제마다 앞 단계라도 해내는 편이 소수 과제 완벽보다 유리.
2. **다과제 학습 + 과제 정보**: 두 팀 모두 과제를 섞어 학습할수록 좋아졌다. 1위는 과제 임베딩, 평가기는 `task_id` 를 관측에 넣어 준다.
3. **실행 방식**: receding horizon(묶음 일부 실행 후 재추론)이 temporal ensembling 보다 나았다(2위 실험). GR00T 베이스라인 기본값은 temporal ensembling 이다.
4. **해상도**: 2위 실험에서 720/480 입력이 224 보다 성공률 2배. 대신 느리다(평가 FPS 20.6 vs 24.6, RGB 기준).
5. **싼 규칙의 효과**: 헛잡기 뒤 그리퍼 열기 규칙 하나로 일부 과제 성공률 약 2배(1위). 규칙은 래퍼가 아니라 정책 쪽에서 proprio·영상만 보고 판단해야 관측 제한에 맞다(해석).
6. **공개 체크포인트에서 출발**: 1위·2위 체크포인트가 Apache-2.0 으로 공개돼 있고, 2025 과제(=2026 의 0~49번)를 RGB+proprio 만으로 학습했다 → 2026 관측 규칙에 맞는다. 16GB GPU 한 장으로는 처음부터 학습이 어려우니 **이 체크포인트를 2026 평가기에 붙여 0~49번을 먼저 채우는 것**이 가장 현실적인 출발점으로 보인다. 확인할 점: (a) 2025 평가기(`omnigibson.learning`) 기준 코드라 2026 관측 키·로봇 이름·배치 차원에 맞게 서버를 손봐야 함, (b) 2026 데모의 속도 필드 수정(07/27, 08/24)으로 proprio 분포가 2025 와 다를 수 있음, (c) 제한시간이 2배→1.5배로 줄어 점수가 떨어질 수 있음, (d) 남의 공개 모델로 출발하는 것을 막는 규정은 없지만 README 에 출처를 밝히는 것이 맞다. 2026 리더보드에도 "OpenPI Comet dual"(AIRI) 제출이 있다.
7. **평가 시간 확보**: 1,000 에피소드는 한 대로 며칠~열흘 단위. 마감(10/17 20:59 KST)까지 역산해서 평가 시작일을 정해야 한다.
