# ovdet — 독립 물체 검출기 (YOLOE, TensorRT FP16, C API)

> 지금 상태: 물체 인식은 YOLOE(이 문서, 코드는 그대로 있음)에서 FastSAM-s 416 + SigLIP 2 B/32(`src/scene_graph/clip`, 진행 중)로 옮기는 중이다. 물체 벡터는 원래 임베딩을 그대로 쓰고, 이름은 기억 폴더 `cache/` 에 둔다. 아래 FastSAM+CLIP 비교는 그 전 기록이다.

scenemap 이 부르는 검출기다. 코드는 `src/scene_graph/ovdet`(README 영어), 형식은 `docs/scenemap_설계.md` 4.2 `sm_detections` 다.

## 2. 검출기 단위 비교 (같은 영상, 정답 장면 기준)

- **영상**
  - ep0(turning_on_radio): 0~40 s 를 5 프레임마다, 240 장.
  - ep200(picking_up_trash): 전체를 15 프레임마다, 512 장.
- **정답**
  - 깊이 화소(2 px 격자)를 정답 카메라 자세로 map 에 올린다.
  - `gt_scene.label` 로 화소마다 정답 물체를 붙인다.
  - 한 프레임에서 한 물체가 격자 화소 20개 이상이면 '보임' 1건으로 센다.
- **지표**
  - 찾음: 마스크 IoU ≥ 0.5 인 검출이 있다.
  - 이름 맞음: 찾았고, 그 검출 이름이 물체의 synset 이거나 BDDL 조상 synset 이다(예: table ⊃ coffee_table). 구조물 별칭 4개(액자·스위치·계단·등)도 맞음으로 친다.
  - 이름 정밀도: 한 정답 물체에 50% 이상 걸친 검출 가운데 이름이 맞는 비율이다.
  - 조각남: 한 물체에 50% 이상 걸친 검출 수의 평균과, 2개 이상인 비율이다.
  - 작은 물체: 원 해상도 1500 px 미만인 물체다.
- **프롬프트**: 과제 BDDL 물체와 구조물 18개(`config/task_prompts.txt`). `allp` 만 어휘 272개 전부를 쓴다.
- **도구**: `src/scene_graph/ovdet/scripts/eval_linux.sh`, `eval_conf.sh`.

- **엔진 확인**: 어휘 22개 엔진과 272개 엔진은 같은 프롬프트에서 결과가 같다. 11s 는 모든 수가 같고, 11l 은 이름 정밀도 표본 2694 대 2690 으로 FP16 차이만 난다. 그래서 **272개 엔진 하나를 두고 프롬프트로 켜고 끄면 된다**.
- **지연**: GPU 이벤트 기준이다. 업로드·letterbox·망·후처리·비트 내리기(호스트)를 다 넣은 값이다. p99 는 한 프로세스에 핸들 여러 개가 같이 돌 때 잰 값이다.

### 좋아진 것 (FastSAM+CLIP → YOLOE)

- **이름이 크게 낫다**: 과제 물체 이름 0.15 → 0.35~0.45, 이름 정밀도 0.21 → 0.45~0.63.
  - CLIP 은 캔·탁자·라디오를 대부분 'baseboard'·'radiator' 로 불렀다.
- **조각남이 준다**: 평균 2.90 → 1.2~1.9.
- **메모리**: 506 → 104~184 MB.
- **지연**: 11s·11m 은 FastSAM 보다 빠르다.
- **ep200 과제 물체**: 캔·쓰레기통을 이름까지 맞힌다(11m 0.10: 캔 51건·쓰레기통 21건 모두 맞은 이름). FastSAM 은 캔 15건만 이름이 맞았다.

### 나빠진 것 (숨기지 않음)

- **ep0 라디오를 전혀 못 찾는다.** 과제 프롬프트 'radio receiver' 로는 모든 크기·conf 0.05 까지 찾음 0 이다.
  - 어휘 272 전부를 켜면 찾는다. 다만 이름이 'satchel' 로 붙는다(125건).
  - FastSAM 은 찾았지만 이름이 'radiator' 였다.
  - 과제 대상 물체이므로 **가장 큰 문제**다. 후보: 프롬프트에 'radio' 같은 동의어를 어휘로 더한다(재 export 필요), 또는 과제 물체만 conf 를 더 낮춘다.
- **이름 없이 '무엇이든 찾는' 재현율은 FastSAM 이 높다**: 비구조물 전체 0.44 대 0.18~0.43(0.10 이하에서 비슷해짐).
- **구조물**(벽·바닥 등)도 FastSAM 0.42 대 YOLOE 0.15~0.43 이다. 다만 scenemap 은 구조물을 2D 지도로 다루므로 영향이 작다.
- **coffee_table 을 'floor'·'rug' 로 부른다**(11l 0.25 에서 200건). 위에서 본 낮은 탁자다. 정답 상자 안 바닥 점이 섞였을 가능성도 있어 확인이 필요하다.
- **conf 를 낮추면** 재현율은 오르지만 조각남과 이름 정밀도가 나빠지고, p99 가 늘어난다(후보가 많아져 11m 21 ms).

### 권고

- 기본은 **YOLOE-11m, 272 어휘 엔진, conf 0.10**이다. 과제 물체 이름 0.42, 작은 물체 0.26/0.25, p50 4.6 ms, 176 MB 다.
- 라디오 문제는 5절 1번으로 푼다.

## 3. YOLO-World 를 넣지 않은 이유

- YOLO-World(Ultralytics `yolov8*-worldv2`)는 **분할 머리가 없다**. 상자만 낸다. 그래서 4.2 계약(마스크)을 채우려면 SAM 계열 분할기를 하나 더 붙여야 한다.
- 그러면 지연·메모리가 두 망 합이 된다. YOLOE 가 같은 텍스트 프롬프트 방식에 분할까지 한 망에서 하므로 우선순위를 낮췄다.
- 필요하면 `tools/export_yoloe.py` 와 같은 방식으로 상자만 비교할 수 있다(남은 것 5절).

## 4. 검증 상태

- **ovdet 내부**: 어휘 22 엔진과 272 엔진의 결과가 같다(위). 스모크(`ovdet_smoke`)는 통과했다.
- **Ultralytics 원본 예측과 대조**(`tools/ref_check.py`): 작성만 하고 **돌리지 않았다**.
  - 마스크는 격자 최근접, Ultralytics 는 retina 쌍선형 업샘플이라 가장자리 차이가 예상된다.
  - 기대: 상자 IoU ≈ 1, 마스크 IoU 0.9 이상.

## 5. 남은 것 (다음에 이어서)

1. **ep0 라디오 미검출**: 어휘에 'radio' 등 동의어를 더해 재 export → 재빌드 → 비교를 다시 돌린다. 과제 물체 conf 를 따로 두는 것도 검토한다.
2. `tools/ref_check.py` 로 Ultralytics FP32 원본과 대조한다(3 프레임, CPU).
3. coffee_table→floor 가 정답 라벨 문제인지 확인한다(정답 상자 아래 바닥 점).
4. 권고 설정(11m·0.10)을 `ovd_default_config` 에 넣을지는 scenemap 쪽 채점(물체 위치·DA)을 보고 정한다.
5. scenemap 연결은 `src/scene_graph/runtime`(sgrt)이 한다(키프레임마다 머리 RGB 로 `ovd_detect` → scenemap). 필요하면 머리·손목 카메라마다 핸들을 따로 둔다.
6. YOLO-World 상자 전용 비교(선택).
