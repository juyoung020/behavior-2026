## 규칙 요약 (GT·SLAM)
- 학습 시: GT(분할, 물체/로봇 pose, 점군 등) 자유 사용. 단 배포 데모엔 월드 pose·분할 없음 → 원본 HDF5를 `OmniGibson/scripts/learning/replay_obs.py`로 재생해 추출
- 데모에 있는 것: `observation.state`(61, 관절·로봇기준 base 속도), `robot2cam_pose`(카메라 3대 상대 pose), `action`(23)
- 평가 시: RGB·depth·proprio만. 로봇 global pose, 물체 pose, GT 분할 금지. 래퍼 코드 수동 검사함
- SLAM·LLM 호출 허용(직접 구현). 사전 제작 지도 허용 여부는 Discord #support 스레드 답변 확인 필요
- BDDL 과제 정의는 평가 때도 사용 가능

## 구조 (프로세스 2개)
1. **정책 서버**: 학습된 모델(π0.5 / GR00T)을 웹소켓 서버로 띄움 (port 8000)
2. **평가기**: OmniGibson이 장면을 돌리며 서버에 관측을 보내고 행동을 받음 → 롤아웃별 metrics JSON + MP4 생성

제출물 = metrics JSON + MP4 링크 + 래퍼 코드 + 로봇 설정(r1pro.yaml) + README, 그리고 주최측 재평가용 Docker 또는 IP(포트 50개).

## 단계
1. 등록 폼 제출
2. BEHAVIOR-1K 설치 (Windows 지원): 관리자 PowerShell에서
   `.\setup.ps1 -NewEnv -OmniGibson -BDDL -JoyLo -Dataset -Eval` (`-Eval` 은 `-JoyLo` 를 요구한다)
   - 이 PC에서는 Isaac Sim 단계에서 멈춰 나눠서 설치했다 → [설치기록.md](설치기록.md)
   - 에셋 zip 31.5GB + 압축해제 + Isaac Sim → **디스크 최소 ~80GB 필요**
3. 동작 확인: `python -m omnigibson.examples.robots.robot_control_example --quickstart`
4. 기본 제공 체크포인트(π0.5, turning_on_radio 과제)로 서버 띄우고 평가 1회 돌려보기
   - π0.5 서버(OpenPI, JAX)는 **Linux 전용** → WSL2 Ubuntu에서 실행, 평가기는 Windows에서 localhost로 연결
5. 몇 개 과제 골라 학습·평가 → 제출
