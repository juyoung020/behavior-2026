# 실험 — π0.5 는 어떤 지시 형식을 따르나 (오프라인, 시뮬레이터 없음, 2026-09-29)

plan.md 5.1 "π0.5 가 '몇 m 앞으로' 같은 지시를 따를 수 있나"를 시뮬레이터 없이 시연 데이터로 바로 본 실험.
시연 단계 구간 안의 프레임마다 π0.5 에 **같은 관측(카메라 3장·상태)** 과 **형식만 다른 문장**을 넣고, 예측 행동 묶음(32 스텝)을 시연 행동과 비교했다(open loop).

## 결론

1. **두 체크포인트 모두 문장을 거의 따르지 않는다.** 같은 관측에서 문장만 바꿨을 때 행동이 바뀌는 정도가, 같은 문장을 한 번 더 넣었을 때(추론마다 다른 난수 = 잡음 기준)와 비슷하다.
   - 공식 radio 체크포인트: 문장을 바꾼 변화 / 잡음 = 이동 1.1~1.4배, 팔 1.0~1.1배.
   - Comet pt50: 이동 1.3~1.6배, 팔 1.1~1.2배 — 조금 더 반응하지만, **맞는 단계 기술(②)과 틀린 단계 기술(⑤)이 비슷하게 바뀐다** → 문장 내용을 따른다고 볼 수 없다.
2. **숫자 명령(④)은 도움이 안 된다.** pt50 은 오히려 이동 방향이 시연과 덜 맞는다(cos 0.71 → 0.54). radio 체크포인트는 차이 없음(0.96 → 0.93).
3. **학습 문장 ⓪ "turning on radio" 와 서빙 문장 ① 긴 과제 문장은 구별되지 않는다**(두 모델 모두 차이가 잡음 수준). 제공 radio 체크포인트가 어느 문장으로 학습됐는지는 이 실험으로 가려지지 않는다 — 모델이 문장을 거의 안 보기 때문이다.
4. 행동은 영상·상태가 정한다. radio 체크포인트는 시연에 매우 가깝고(이동 방향 cos 0.96, 회전 부호 100 % 일치) pt50 은 덜 가깝다(0.71, 87 %). pt50 쪽 이동 차이는 2025 학습 데이터(base_qvel 월드 좌표)와 2026 데이터(로봇 기준)의 좌표계 차이 영향일 수 있다(추정, [2025상위팀_깃허브.md](2025상위팀_깃허브.md) 2.9절 #3).
5. 따라서 **지금 체크포인트로는 "Qwen 이 문장으로 π0.5 를 조종"하는 스펙이 작동하지 않는다.** 문장으로 조종하려면 재라벨 + 파인튜닝(plan.md 5.1 (가))이 필요하고, 이동만 따로 제어기로 채우는 (나)가 학습 없이 가능한 길이다.

주의(해석 범위): 표본은 학습에 쓰였을 수 있는 시연이다(두 모델 모두 radio 시연으로 학습). 이 실험은 "일반화"가 아니라 "같은 장면에서 문장을 바꾸면 행동이 바뀌나"만 본다. open loop 라 실제 수행 성공과는 다르다.

## 1. 방법

| 항목 | 내용 |
|---|---|
| 데이터 | `data/2026-challenge-demos` 과제 0(radio) 시연 앞 20개(에피소드 0~19). 주석 `annotations/task-0000/*.json` 의 `skill_annotation` 단계 4개(move to → pick up from → press → place on)와 프레임 구간 |
| 표본 | 단계 구간의 1/3·2/3 지점 프레임 → 20 × 4 × 2 = **160 표본** |
| 관측 | 카메라 3장(머리 720²·손목 480² 영상 → `openpi_client.image_tools.resize_with_pad` 로 224², 평가 때 서버가 하는 것과 같음), 상태 = `observation.state` 61차원(2026 평가기 proprio 와 같은 순서) |
| 정답 | 그 프레임부터 32 스텝의 시연 `action`(23차원) |
| 추론 | 모델마다 정책을 한 번 올려 1,120 줄(160 표본 × 7 형식)을 차례로 `policy.infer`. 웹소켓 서버는 안 거침(전송은 측정 대상 아님) |
| 지표 | 시연과의 평균 절대 차(이동 3·몸통 4·팔 14·그리퍼 2), 이동 방향 cos(묶음 평균 vx, vy), 회전 부호 일치, **① 대비 변화량**(같은 관측에서 ① 문장 때 예측과의 차 = 문장 민감도), 지시 이동량(④에 넣은 값)과 예측 이동 방향의 cos |

형식 7개 (예: move to 단계, 에피소드 0 프레임 88):

| 형식 | 문장 |
|---|---|
| ⓪ 과제 이름 (2026 데모로 openpi 를 학습할 때 들어가는 문장 — 학습 가속 에이전트 확인: `lerobot_compat.py:17-25` 가 tasks.parquet 이름을, `tokenizer.py:23` 이 "_"→" ") | `turning on radio` |
| ① 과제 문장 (서빙 문장, openpi `configs/tasks/b1k.py:5`, Comet `task_mapping.json`) | `Turn on the radio receiver that's on the table in the living room.` |
| ①' ① 한 번 더 — **잡음 기준**: openpi 정책은 호출마다 난수를 새로 나눠 쓰므로(`policies/policy.py:65,75`) 같은 문장도 결과가 조금 다르다 | ① 과 같음 |
| ② 기술 + 물체 (Comet 하위과제 형식, 시연 주석 어휘) | `move to the radio` |
| ③ 목적 / 예상 행동 (사용자 제안) | `Purpose: to turn on the radio receiver on the table. Expected action: move to the radio.` |
| ④ 숫자 명령 (그 프레임→단계 끝까지 시연의 base_qvel 적분 이동량, 로봇 기준) | `move to the radio: go forward 0.5 m, 0.2 m to the right, turn left 53 degrees` |
| ⑤ 다른 단계의 기술 (대조 — 문장을 따른다면 행동이 그쪽으로 바뀌어야 함) | `pick up the radio from the coffee table` |

## 3. 재현

실험이 끝나 도구는 [archive/](../archive/README.md) 로 옮겼다(되살리는 법은 그 README). 아래 경로는 archive 안 경로다. 스크립트 안 경로(`tools/…`, `src/agent/probe`)는 옮기기 전 그대로라 되살려서 돌린다.

```
# 한 명령 (없으면 표본 준비 → prompt 생성 → 추론 → 채점·표). 스크립트 안 저장소 경로를 ~/behavior-2026 으로 고치고 정책 저장소(.venv)·체크포인트를 갖춰야 돈다(미확인).
bash archive/tools/run_probe.sh pt50  20 2
bash archive/tools/run_probe.sh radio 20 2
# 결과: logs/probe_<모델>_<시각>.md (+ _meta.json, _gpu.csv). 표본·예측은 data/probe/ (git 제외, 표본 72 MB)
```

| 파일 | 언어 | 역할 |
|---|---|---|
| `archive/src/agent/probe/` (`probe prompts`, `probe report`) | Rust | 형식별 문장 만들기(물체 이름·숫자 명령·대조 문장), 지표 계산, 표 쓰기 |
| `archive/tools/probe_prep.py` | 파이썬(일회성) | 시연 parquet·HEVC 영상에서 표본 뽑기(약 1분, CPU) |
| `archive/tools/probe_infer.py` | 파이썬(접착부) | 정책 저장소 `.venv` 로 `policy.infer` 만 부름(JAX 정책이라). 입력 키: Comet `observation/egocentric_camera` 등, 공식 openpi `observation/image_0·1·2` |
| `archive/tools/run_probe.sh` | bash | 위를 한 명령으로 + nvidia-smi 1초 기록 |

시간: 표본 준비는 한 번, 모델마다 로딩+컴파일 + 1,120 번 추론 — 이 PC 에서 다시 잴 것.

## 4. 다음

- 잡음 기준을 없애 더 날카롭게: Comet 정책은 `infer(obs, noise=...)` 를 받는다(`src/openpi/policies/policy.py:68`) → 표본마다 같은 잡음을 모든 형식에 넣으면 "① 대비 변화"가 순수하게 문장 효과만 된다. 공식 openpi 정책은 이 인자가 없어 난수 키를 표본마다 고정하는 방식이 필요.
- 문장을 따르는 모델이 필요하면: 시연 주석 단계 구간 + base_qvel 적분으로 ②·④ 형식 문장을 붙여 파인튜닝(plan.md 5.1 (가), 외부 GPU) → 같은 도구로 전후 비교.
- 1위 모델(문장 대신 단계 번호)은 제외했다. 단계 번호 입력으로 같은 틀(맞는 단계 vs 틀린 단계)을 돌리면 "단계 조종"이 되는지 볼 수 있다.
